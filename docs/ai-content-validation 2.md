# AI 内容校验

## 六层闸门

1. API 输入 Schema：数量、枚举、长度、数组和额外字段。
2. JSON 输出 Schema：严格字段、tuple 四选项、正确索引和结构长度。
3. 服务端业务规则：语言方向、假名、等级、例句、题目来源、唯一干扰项和请求摘要重复。
4. 完整本地库规则：再次对比全部内置内容和累计 AI 内容；跳过重复项并继续生成缺少数量。
5. 可选质量复核：Quality 模型输出 pass/needsRepair/reject；只审查最终内容。
6. 用户纠错：查看来源、删除、移出库、重新生成、反馈问题和撤销批量保存。

## 词汇

归一化使用 NFKC、小写并移除空白/标点；分别比较日语写法、假名、英语词、中文释义和内容哈希。服务端先按随请求发送的摘要过滤，客户端再与完整内置词库和历史 AI 词库比较；重复项不会入库，并会触发补足请求。规则还检查假名字符、日/英字段方向、中文格式、例句不等于词、日英例句不完全相同、无 Markdown/模型前缀。

## 语法与对比

检查语言与请求一致、日英等级标签合法且匹配请求、标题不重复、易混淆项不是自身、练习选项唯一。日英对比拒绝“完全相同/逐字对应/一一对应”等错误声明，并要求可识别难度。

## 测试题

题目 `source/sourceId` 必须存在于服务端收到的来源摘要，单语言模式必须一致；四项归一化后唯一，correctIndex 有效，同批题干/选项哈希不能重复。错误题不会加入测试会话。

## 失败语义

- 全部通过：`succeeded/passed`。
- 修复后通过：`validationStatus: repaired`。
- 只通过一部分或模型少返回：自动按缺少数量继续生成；达到补足尝试上限后仍不足才显示 `partial`。
- 全部不通过：`CONTENT_VALIDATION_FAILED`，不保存业务内容。

临时内容也必须通过同样校验；“不保存”不是跳过质量闸门。
