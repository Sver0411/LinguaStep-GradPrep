# LinguaStep 使用体验审查

审查日期：2026-10-23。版本：v0.16.0，仓库提交 `2d9fe4f`。源码已下载到 `/Users/mac/Documents/ChatGPT/LinguaStep`。

审查方法：实际运行本地项目，在 Chrome 体验桌面首页、词卡揭示、英语练习及设置；用 400px 设备预览检查手机设置和单语词卡；抽查题库、资料与学习流程。竞品依据官方公开资料，不宣称完整实测所有竞品。没有进行长期学习实验，也没有测出实际记忆效率提升百分比。手机预览不等同于真机测试。

## 判断

现有产品已具备日常学习工具的基本框架：每日计划、连续下一步、复习、错题、收藏、统计、离线本地记录都有。最明显的差距在于内容与目标的匹配、有效回忆的检验、学习材料之间的连接，以及长期使用的可靠性。继续增加菜单和词条数量，收益可能低于把已有学习闭环补完整。

适合先明确为“有一定基础的中文用户，围绕一个主要考试目标学习，日英对照用于辅助理解”。日语 N1/N2/N3 加英语四级/六级/TOEIC 同时做成完整课程，对个人项目的内容维护要求很高。

## 优先问题与建议

| 优先级 | 已核实的现状 | 对使用者的影响 | 建议和验收标准 |
| --- | --- | --- | --- |
| P0 | 英语外部题库把七八年级题标成 CET-4、九年级题标成 CET-6；练习页把对应等级的 416 题汇总为“真题”。实际六级页面抽到“Don't get off the bus … it has stopped.”等基础题 | 正确率不能据此解释为四六级备考水平；花时间刷题却可能练错难度 | 将这批题改为基础英语练习；只有经核实的对应考试材料才进入考试专项。“真题”应区分官方历年题、教辅题和原创题，展示年份或具体来源；各等级抽样校准 |
| P0 | 手机单语词卡进入时，已经出现日语答案与例句，底部仍显示“揭示答案”；桌面同一阶段会隐藏答案 | 直接削弱回忆过程，用户可能把看懂答案当成能回忆 | 日语/英语/双语三个模式都先遮住答案及泄露答案的例句、读音；点击后才揭示。桌面与窄屏各走一遍验收 |
| P1 | 高频词书有查阅、朗读、收藏，但没有统一进入背词调度；词书收藏与核心单词收藏分开呈现 | 查到想学的词仍不能自然进入每日复习；增加查阅内容未必增加可学习内容 | 查词→加入学习→出现在今日新词或后续计划→产生复习记录。重复导入应识别已有词，保留进度 |
| P1 | 日英对照分步揭示后，对整组只有一套“认识/模糊/不认识”反馈 | 日语认识、英语不会时无法准确评分，可能反复复习已会的一侧 | 默认按主语言评分，另一侧可展开参考；或让两侧分别评分、分别安排复习。已有单语言轨迹值得保留 |
| P1 | 训练主要是自评词卡及四选一；没有完整的听力训练，阅读每级仅少量原创题；英语也没有覆盖写作和翻译训练 | 会做熟题不一定能听懂或在新语境认出；难以支撑完整备考定位 | 先增加短句听辨、听写或挖空，再增加未见过的短文迁移测试。按一个考试目标补齐关键题型，避免一次扩充所有考试 |
| P1 | 桌面有 JSON 备份导入导出，手机设置页只有语言、新词量、练习量，缺少备份入口；数据存于当前浏览器 | 手机用户难以备份。电脑和手机采用同一数据模型，不等于自动跨设备同步 | 先补手机备份、恢复和最近备份时间。个人自用可先保留手动备份；若开放给更多人长期使用，再提高同步优先级 |
| P2 | 每日计划已有复习积压时减少新词、周末调整，不是完全固定计划；但用户主要配置题数与词数 | 用户很难判断今天实际要花多久，考试目标和每日任务连接仍弱 | 提供每天 10/20/30 分钟预算、一个主目标、可选考试日期；按最近实际完成耗时调整计划，显示原因并允许临时减量 |
| P2 | 统计主要展示学词量、题量、连续天数、掌握数和总体正确率 | 数据能说明做了多少，较难回答过几天还记得多少、哪里需要加强 | 增加 7/30 天延迟回忆表现、首次作答正确率、重复错因、听力/词汇/阅读分类；直接链接到对应练习。不要把自评连续认识直接表达成能力认证 |

这里的 P0/P1/P2 是产品建议排序，不是代码漏洞等级。上表保留 v0.16.0 审查时的现状，后续实现状态见下节。

## 推荐实施顺序

第一批：纠正英语等级与真题标注，修手机词卡提前显示答案，补手机备份入口。完成标准是学习结果不再被错误标签或答案泄露干扰，手机用户能自行导出恢复。

第二批：词书加入复习、双语独立反馈、统一错题到知识点的入口。完成标准是任何一个想学的词都能从发现进入复习，日英一强一弱时能准确记录。

第三批：选一个主目标，例如 N2，加入短句听辨和新语境测试；计划按时间预算分配，统计展示延迟表现。新增功能应围绕这一目标，不先扩展社交、排行榜、AI 会话或所有考试题库。

评估效率时，可记录同样 15 分钟内完成多少“首次回忆成功”的项目，以及一周后在新题面中的回忆表现。先收集自己的基线，不能预先保证提高某个百分比。

## 发音问题：本轮已按后续要求处理

本地版本改为服务端 Microsoft Edge 在线神经语音：日语 `ja-JP-NanamiNeural`（七海），英语 `en-US-JennyNeural`。支持任意日英句子，每次最多 1200 字符，不需要配置 Key。已移除系统语音兜底，修正媒体策略对 Blob 音频的支持，增加错误反馈、缓存、合并请求和超时。尚未部署到公开站点。

用户已确认听感符合期望，并选择继续使用当前方案。

网上资料能确认：MOJi 官方帮助说发音支持本地 TTS 和在线音频，产品说明出现“七海”音色；微软公开音色表有 Nanami。只能据此推断值得采用相同音色，不能认定 MOJiTest 与识日一定使用了同一个 API。识日官网没有披露具体供应商。

- [MOJi 官方发音帮助](https://www.shareintelli.com/mojidict/android-pronunciation-issues)
- [微软音色表](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=text-to-speech)
- [msedge-tts 项目](https://github.com/Migushthe2nd/MsEdgeTTS)
- [识日官网](https://shiri.app/)

当前 Edge 链路免 Key，无需付费账户；属于社区接入，不是承诺永久免费无限量的正式开发者 API。按用户要求不接入 Azure 正式 API。

技术验证：类型检查和变更文件 ESLint 通过；新增语音相关测试 6 项通过。实际服务端接口日语与英语自定义句子均返回 200、对应音色标头与有效 MP3。组件回归 19 项中 15 项通过、4 项失败；在原始提交的临时副本复跑得到完全相同的 4 项失败，未在本轮扩大修复范围。
